# State of AI Builders — Monthly Report

> Plan §8 #7: a monthly "State of AI Builders" report, generated automatically from live data, published on the 1st of each month.

The State of AI Builders is a single Markdown file per month, surfaced
three places:

1. **The blog app** (`/blog/state-of-ai-builders-2026-06`) — via
   `POST /v1/admin/content/blog` from the publish script.
2. **The marketing site** (`/blog/2026-06`) — the page renders the
   `.md` file under `web/site/src/content/reports/`.
3. **Direct download** — the `.md` file is committed to
   `web/site/src/content/reports/` and tracked in git, so the report is
   always available even if the orchestrator is offline.

---

## Data flow

1. **Cron job** (`internal/jobs/statereport/scheduler/scheduler.go`,
   cron `0 9 1 * *`) runs at 09:00 UTC on the 1st of each month. It calls
   the builder with the last day of the previous month as the reference
   date, so the June 2026 report is generated on **July 1 09:00 UTC**.
2. **Builder** (`internal/jobs/statereport/report.go`) reads the live
   city + university ranking tables and the `city_ambassadors` table. No
   separate aggregation layer is needed because the hourly recompute
   job already maintains the rows the report consumes.
3. **Renderer** turns the `Report` struct into a self-contained Markdown
   string (no external CSS/JS). The renderer handles section
   omission: empty sections (e.g. no new metros this month) are skipped
   so the report stays readable.
4. **Disk write** — the file is written to
   `STATE_REPORT_OUTPUT_DIR` (default `web/site/src/content/reports`)
   so the marketing site picks it up at build time.
5. **Blog publish** — `scripts/publish_state_reports` reads the same
   `.md` files and inserts them into `blog_posts` via the existing
   `INSERT … ON CONFLICT (slug) DO UPDATE` upsert.

## Sources

| Section | Query |
|---|---|
| TL;DR — metros ranked | `SELECT count(*) FROM city_rankings WHERE period_end = latest AND ranking_category = 'composite' AND active_users >= 5` |
| TL;DR — universities ranked | `SELECT count(*) FROM university_rankings WHERE period_end = latest AND ranking_category = 'composite' AND active_users >= 5` |
| TL;DR — active / new / deploys / execs | summed from the same per-row query |
| Top 10 metros | `SELECT * FROM city_rankings WHERE period_end = latest AND ranking_category = 'composite' AND active_users >= 5 ORDER BY rank_position LIMIT 10` |
| Top 10 universities | analogous |
| New metros | `city_rankings` rows for the latest period that don't exist in the previous period (or were below the k=5 threshold). |
| New ambassadors | `SELECT * FROM city_ambassadors WHERE promoted_at >= month_start AND promoted_at < month_end` |
| Gainers / losers | existing `ListMovers("gainers"/"losers", 5, composite)` |

## Privacy

The report uses the same `MinActiveUsersForPublic = 5` threshold as the
leaderboard. A metro with fewer than 5 active opted-in builders is
**omitted** from every section it would otherwise appear in (top list,
new metros, movers, etc.). The headline numbers reflect only metros that
pass the threshold, so the report never leaks the exact count of an
under-threshold metro.

## Environment

| Variable | Default | Purpose |
|---|---|---|
| `STATE_REPORT_CRON` | `0 9 1 * *` | When the cron runs. |
| `STATE_REPORT_OUTPUT_DIR` | `web/site/src/content/reports` | Where the `.md` files are written. |
| `STATE_REPORT_ENABLED` | `true` | Set to `false` to skip scheduling entirely. |
| `BLOG_AUTHOR_ID` | `a1b2c3d4-e5f6-7890-abcd-ef1234567890` | blog_posts.author_id for the publish script. |

## CLI

```bash
# Generate the current month's report (writes to STATE_REPORT_OUTPUT_DIR).
go run ./scripts/generate_state_report

# Backfill a specific month.
go run ./scripts/generate_state_report --month 2026-05

# Custom output dir.
go run ./scripts/generate_state_report --out /tmp/reports

# Publish all .md files in the default dir to blog_posts.
go run ./scripts/publish_state_reports
```
