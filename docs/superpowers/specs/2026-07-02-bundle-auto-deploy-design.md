# Bundle Auto-Deploy: Automated Provider Deployment on Payment

**Date:** 2026-07-02
**Status:** Draft
**Scope:** Automate deployment of bundle function templates to the user's connected provider (Cloudflare Workers, Vercel, Deno, Fly) when a bundle subscription is purchased via Stripe.

---

## Problem

When a user purchases a bundle (saas-starter, marketplace, ai-app), the system creates app records and function templates in the database but never deploys the code anywhere. The backend URL points to `https://api.functionfly.io/v1/apps/{id}` which is a placeholder. The health check fails (`error code: 1042` on CF Workers), the circuit breaker opens, and the user gets `SERVICE_UNAVAILABLE` on their app URL.

The gap: **no code is deployed to any provider after payment**.

## Approach

Hybrid synchronous/asynchronous deployment with a state machine on the `bundle_subscriptions` table:

1. **Stripe webhook** creates app + function records + subscription (fast, existing flow)
2. **If provider selected at checkout** → deploy immediately (async goroutine with DB state tracking)
3. **If no provider** → subscription enters `awaiting_provider` state → dashboard prompts user to connect → deployment triggers on provider connection
4. **Retries with exponential backoff** for transient failures
5. **Idempotency guard** prevents double-deploy on duplicate webhooks

### `bundle_function_templates` — new table

Move hardcoded function templates from Go code to the DB for independent iteration:

```sql
CREATE TABLE bundle_function_templates (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    bundle_slug TEXT NOT NULL,

    runtime TEXT NOT NULL DEFAULT 'js',
    code TEXT NOT NULL,
    route_path TEXT NOT NULL,

    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),

);
```

### State machine

```
checkout.session.completed
    ↓
[provisioning] ──has provider──→ [deploying] ──success──→ [deployed] → [active]
    ↓                                    ↓
[awaiting_provider]              [failed] ──attempts < 3──→ [deploying] (after backoff)
    ↓                                ↓
user connects provider ──→ [deploying]   (attempts >= 3 → stays failed, manual retry)
```

## Worker Script Generation

### Cloudflare Workers (Option A — native CF APIs)

Each bundle's templates are combined into a single worker with URL-based routing:

```javascript
// Auto-generated by FunctionFly — do not edit
import { KVNamespace } from '@cloudflare/workers-types';

export interface Env {
  STATE: KVNamespace;
  AI: Ai;
}

export default {
  async fetch(request: Request, env: Env): Promise<Response> {
    const url = new URL(request.url);
    const path = url.pathname;

    if (path === '/stripe-webhook') return handleStripeWebhook(request, env);
    if (path === '/welcome-email') return handleWelcomeEmail(request, env);
    return new Response('Not found', { status: 404 });
  }
};

async function handleStripeWebhook(request: Request, env: Env): Promise<Response> {
  // Template code adapted to use env.STATE.put/get instead of state.set/get
}

async function handleWelcomeEmail(request: Request, env: Env): Promise<Response> {
  // Template code adapted to use CF Email API or fetch to external provider
}
```

Template adaptation rules:
- `state.set(key, val)` → `env.STATE.put(key, JSON.stringify(val))`
- `state.get(key)` → `JSON.parse(await env.STATE.get(key))`
- `ai.chat.completions.create(...)` → `env.AI.run('@cf/meta/llama-3-8b-instruct', ...)`
- `email.send(...)` → fetch to a webhook or CF Email Workers binding

### Vercel / Deno / Fly (Option B — runtime shim)

Deploy a FunctionFly runtime shim alongside user code. The shim provides `state`, `ai`, `email` abstractions that proxy back to FunctionFly APIs via HTTP. Adds latency and a dependency on FunctionFly being up, but works across all providers.

For MVP: implement Option A (CF Workers) only. Vercel/Deno/Fly support added later.

## Provider Selection

### Checkout page

The dashboard checkout page adds a provider selector:

```
┌─────────────────────────────────────┐
│  Deploy to:                         │
│  ○ Cloudflare Workers  [connected]  │
│  ○ Vercel              [connect]    │
│  ○ Deno Deploy         [connect]    │
│  ○ Fly.io              [connect]    │
└─────────────────────────────────────┘
```

Only providers with `status = 'active'` in the `providers` table are selectable. If no provider is connected, the only option is "Connect a provider first" which redirects to the provider connection flow.

Selected provider + provider_id go into Stripe session metadata:
```
metadata.bundle_slug = "saas-starter"
metadata.provider = "workers"
metadata.provider_id = "34465e7e-..."
```

## Deployment Flow

### Path 1: Provider selected at checkout

```
1. Stripe checkout.session.completed webhook fires
2. handleBundleSubscriptionCheckout extracts metadata.provider, metadata.provider_id
3. Creates/updates bundle_subscription with deploy_status = "deploying", provider_id = ...
4. Creates app + function records (existing flow)
5. Calls DeployBundle(subscription) in a goroutine
6. Returns 200 to Stripe immediately
```

### Path 2: No provider at checkout

```
1. Same webhook, but metadata.provider is empty
2. Creates subscription with deploy_status = "awaiting_provider"
3. Dashboard shows "Connect a provider to deploy" banner
4. User connects provider (POST /v1/providers/connect)
5. Handler queries: any subscriptions with deploy_status = "awaiting_provider"?
6. If found: updates subscription with provider_id, sets deploy_status = "deploying"
7. Calls DeployBundle(subscription)
```

### Path 3: Retries

```
1. Background ticker (every 60s) queries:
   SELECT * FROM bundle_subscriptions
   WHERE deploy_status = 'failed'
     AND deploy_attempts < 3
     AND (next_retry_at IS NULL OR next_retry_at <= NOW())
2. For each: calls DeployBundle(subscription)
3. Backoff: attempt 1 → retry in 1min, attempt 2 → 5min, attempt 3 → 15min
4. After 3 failures: deploy_status stays "failed", dashboard shows error + "Retry" button
```

## DeployBundle Implementation

```go
func (h *Handler) DeployBundle(ctx context.Context, sub *storage.BundleSubscription) error {
    // 1. Load provider record
    provider, err := h.repo.GetProvider(ctx, sub.ProviderID)

    // 2. Load bundle templates from DB
    templates, err := h.repo.ListBundleTemplates(ctx, sub.BundleSlug)

    // 3. Validate provider permissions (CF: try listing scripts)
    if err := h.validateProviderAccess(ctx, provider); err != nil {
        return h.failDeploy(sub, "provider access denied: %v", err)
    }

    // 4. Generate combined worker script
    script := h.generateWorkerScript(sub.BundleSlug, templates)

    // 5. Deploy to provider
    switch provider.Provider {
    case "workers":
        return h.deployToCloudflare(ctx, sub, provider, script)
    case "vercel":
        return h.deployToVercel(ctx, sub, provider, script) // future
    default:
        return h.failDeploy(sub, "unsupported provider: %s", provider.Provider)
    }
}

func (h *Handler) deployToCloudflare(ctx context.Context, sub *storage.BundleSubscription, provider *storage.Provider, script []byte) error {
    client := cloudflare.NewDeploymentClient(provider.Token, accountID)

    // Deploy worker
    scriptName := sub.ScriptName // deterministic: {tenant_id_prefix}-{bundle_slug}
    result, err := client.Deploy(ctx, script, scriptName, cloudflare.RuntimeJS)
    if err != nil {
        return h.failDeploy(sub, "deploy failed: %v", err)
    }

    // Enable workers.dev
    if err := client.EnableWorkersDev(ctx, scriptName); err != nil {
        // Cleanup: delete the partially-deployed worker
        client.DeleteDeployment(ctx, scriptName)
        return h.failDeploy(sub, "enable workers.dev failed: %v", err)
    }

    // Build worker URL
    subdomain := h.getWorkersSubdomain(ctx, provider)
    workerURL := fmt.Sprintf("https://%s.%s.workers.dev", scriptName, subdomain)

    // Create backend
    app, _ := h.repo.GetAppByTenantAndSlug(ctx, sub.TenantID, sub.BundleSlug)
    _, err = h.repo.CreateBackend(ctx, app.ID, "workers", "us-east-1", workerURL, "", nil)
    if err != nil {
        return h.failDeploy(sub, "create backend failed: %v", err)
    }

    // Update subscription
    sub.DeployStatus = "deployed"
    sub.DeployedAt = timePtr(time.Now())
    sub.WorkerURL = workerURL
    return h.repo.UpdateBundleSubscription(ctx, sub)
}
```

## Idempotency

Before deploying, check if a backend already exists for this app + provider:

```go
existing, _ := h.repo.ListBackendsByAppID(ctx, app.ID)
for _, b := range existing {
    if b.Provider == "workers" && strings.Contains(b.URL, scriptName) {
        // Already deployed, skip
        sub.DeployStatus = "deployed"
        return h.repo.UpdateBundleSubscription(ctx, sub)
    }
}
```

## Template Adaptation

### State API mapping (CF Workers KV)

| Template API | CF Workers equivalent |
|-------------|----------------------|
| `state.set(key, val)` | `await env.STATE.put(key, JSON.stringify(val))` |
| `state.get(key)` | `JSON.parse(await env.STATE.get(key))` |
| `state.push(key, val)` | `const arr = JSON.parse(await env.STATE.get(key) \|\| '[]'); arr.push(val); await env.STATE.put(key, JSON.stringify(arr))` |

### AI API mapping (CF Workers AI)

| Template API | CF Workers AI equivalent |
|-------------|-------------------------|
| `ai.chat.completions.create({model, messages})` | `await env.AI.run('@cf/meta/llama-3-8b-instruct', { messages })` |
| `ai.embeddings.create({model, input})` | `await env.AI.run('@cf/baai/bge-base-en-v1.5', { text: input })` |

### Email API mapping

No native CF email send. Options:
- **Webhook forward:** POST to a FunctionFly endpoint that sends via Resend
- **CF Email Workers:** bind an email routing address (requires DNS setup)
- **MVP:** skip email for CF deployments, log a warning

## Migration Strategy

1. **Phase 1:** Add DB columns + `bundle_function_templates` table. Migrate hardcoded templates to DB. No behavior change.
2. **Phase 2:** Implement CF Workers deployment (Option A). Modify webhook to trigger deploy. Add retry ticker.
3. **Phase 3:** Add provider selector to checkout page. Add `awaiting_provider` flow.
4. **Phase 4:** Add Vercel/Deno/Fly support (Option B — runtime shim).

---

## Decisions on Open Questions

1. **CF KV namespace:** Auto-create one per deployment (`{script_name}-state`). Isolation between bundles, no key collision, follows CF best practices.
2. **AI binding:** Proxy to FunctionFly API for MVP. CF Workers AI adds per-request cost. FunctionFly already has AI infra. Native CF AI added later as opt-in.
3. **Custom domains:** `*.workers.dev` only from day one. Custom domains are a separate feature (DNS/SSL complexity adds deployment failure modes).
