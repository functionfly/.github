# Backend-in-a-Box Pricing Implementation Plan

Implement pre-configured "bundle" pricing packs that combine multiple FunctionFly features at a discounted flat rate, plus viral pricing tactics (deferred billing, founder mode).

## Proposed Implementation

### Phase 1: Database Schema (1-2 hours)

**New Tables:**

```sql
-- Pre-configured backend bundles
pricing_bundles (
    id UUID PRIMARY KEY,
    slug VARCHAR(50) UNIQUE, -- 'saas-starter', 'marketplace', 'ai-app'
    name VARCHAR(100), -- 'SaaS Starter Pack'
    display_price_cents INTEGER, -- 2900 for $29
    billing_interval VARCHAR(20), -- 'month', 'year'
    description TEXT,
    features_included JSONB, -- ['auth', 'payments', 'user_db', 'email', 'analytics']
    feature_limits JSONB, -- {functions: 10, requests: 1000000, ...}
    icon VARCHAR(50), -- 'rocket', 'shopping-cart', 'brain'
    sort_order INTEGER,
    is_active BOOLEAN DEFAULT true
)

-- Deferred billing configuration (Build Now, Pay Later)
deferred_billing_configs (
    id UUID PRIMARY KEY,
    bundle_id UUID REFERENCES pricing_bundles(id),
    trigger_type VARCHAR(20), -- 'user_count', 'revenue_mrr', 'api_calls', 'time_elapsed'
    trigger_threshold INTEGER, -- e.g., 100 users, 100000 cents ($1000 MRR)
    grace_period_days INTEGER DEFAULT 7,
    convert_to_plan_id UUID -- which plan to convert to after trigger
)

-- Founder mode registrations
founder_mode_registrations (
    id UUID PRIMARY KEY,
    tenant_id UUID REFERENCES tenants(id),
    bundle_id UUID REFERENCES pricing_bundles(id),
    started_at TIMESTAMP,
    ends_at TIMESTAMP, -- NULL if revenue-based
    trigger_type VARCHAR(20), -- 'time' or 'revenue'
    mrr_threshold_cents INTEGER, -- for revenue-based
    status VARCHAR(20), -- 'active', 'converted', 'expired'
    converted_to_plan_id UUID,
    converted_at TIMESTAMP
)
```

### Phase 4: Viral Pricing Logic (2-3 hours)

**"Build Now, Pay Later" Implementation:**

1. **Tracking:**
   - Daily job checks tenant usage against thresholds
   - Track: user count (from state fabric), MRR (from payments volume), API calls

2. **Notification Flow:**
   - At 80% of threshold → Email warning
   - At 100% of threshold → 7-day grace period notification
   - After grace → Convert to paid plan or suspend

3. **Configuration Options:**
   - Users can choose their threshold during signup
   - Options: 100 users / $1000 MRR / 3 months (whichever comes first)

**"Founder Mode" Implementation:**

1. **Two variants:**
   - Time-based: Free for 90 days, then auto-convert to bundle subscription
   - Revenue-based: Free until $1000 MRR detected, then convert

2. **MRR Detection:**
   - Track via integrated Stripe payments volume
   - Manual verification option for external payment processors
