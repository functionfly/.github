- **Multi-region Auto-failover** — Automatic traffic routing when a region experiences issues — <span class="badge badge-in-progress">In Progress</span>

- **GraphQL State API** — Query state with GraphQL alongside REST — <span class="badge badge-design">Design</span>

## How We Prioritize

We balance several factors when deciding what to build next:

1. **User impact** — How many users benefit, and how much?
2. **Strategic alignment** — Does it move us toward our long-term vision?
3. **Technical feasibility** — Can we build it reliably at scale?
4. **Revenue potential** — Does it help us grow sustainably?

We gather input from:
- Direct customer conversations and support tickets
- Feature requests from the dashboard
- GitHub issues and discussions
- Internal product team analysis

## Release Philosophy

**Ship when it's ready.** We don't rush features to hit arbitrary dates. We prefer to communicate delays honestly rather than over-promise.

**Semantic versioning.** Breaking changes are rare and communicated well in advance.

**Deprecation policy.** When we retire features, we give at least 90 days notice with migration guidance.

**Changelog.** We document every significant change in our [changelog](https://functionfly.com/changelog/) and [GitHub releases](https://github.com/functionfly/functionfly/releases).
